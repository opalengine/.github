# Security policy

## Reporting a vulnerability

Please don't open a public issue, pull request or discussion for a security problem.

Report it privately with GitHub's private vulnerability reporting: open the affected repository's
**Security** tab and click **Report a vulnerability**. Only you and the maintainers see the report, and
we can work on a fix with you in a private advisory.

If a repository doesn't show that button, write to hello@opalengine.com with the repository name and
ask for a private channel. Don't put the details in that first email.

A useful report has the affected repository and version, what an attacker can do, and the steps to
reproduce it.

## Supported versions

We fix security problems in the latest release of each project. Older releases don't get fixes;
upgrading is the remedy.

## What to expect

We're a small team, so these are aims, not guarantees:

- We acknowledge a report within a week.
- We tell you whether we accept it and keep you posted while we fix it.
- We credit you in the advisory when it's published, unless you'd rather not be named.

We don't run a bug bounty.
